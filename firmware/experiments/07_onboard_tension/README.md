# 07_onboard_tension

MVP step 1: compute forearm EMG tension on the ESP32-S3. No Wi-Fi.

Sampling as in `06_raw_emg_stream`: 1 kHz continuous ADC (DMA) on GPIO4 (AD8232 OUTPUT), sampler task on core 1, time from the sample index. Each sample goes through `components/emg_dsp` (plain C99, no ESP-IDF API, single-precision float):

| Stage | Setting |
|---|---|
| Mains notches | 60, 120, 180 Hz biquads, -3 dB bandwidth 4 Hz each (Q = 15, 30, 45) |
| Band-pass | 45-200 Hz Butterworth, 4th-order prototype (4 biquads) |
| RMS | 200 ms window, one output every 50 ms (20 Hz) |
| Calibration | Relax baseline = RMS of a 5 s attempt. The first attempt starts 0.5 s after boot (filter settling); a rejected attempt is retried every 2 s until one is accepted; the button on GPIO6 (to GND) starts a new attempt. Accepted only if >= 90 % of its samples are unsaturated, its RMS is below 15 mV, and the coefficient of variation of its 50 ms RMS values is below 0.5. Every attempt is printed with its result and reason |
| Output | `normalized = RMS / baseline`; level 0 relax, 1 medium, 2 hard with hysteresis: medium entered at 1.49x and left below 1.35x, hard entered at 2.72x and left below 2.45x. -1 while calibrating or without a baseline. All ratios are **provisional** (in-sample from experiment 06) |
| Saturation | A window containing any raw sample <= 5 mV or >= 3100 mV is flagged; the last valid RMS, normalized value and level are held |

Filter coefficients: `components/emg_dsp/include/emg_coeffs.h`, generated by `analysis/design_emg_filters.py`.

Serial output (USB-Serial-JTAG), every 50 ms:

```
<sample index>,<rms mV>,<normalized>,<level>,<saturated>
```

and once per second a `# samples= ovf= dropped= bad= dsp_us_frame_avg= dsp_us_frame_max=` line; each calibration attempt is reported as `# calibration attempt N: accepted | rejected: <reason> (valid %, cv, rms); baseline_mv=...`.

## Host test and validation

The host test builds the same `emg_dsp.c` with the Mac compiler and feeds an experiment 06 capture through it:

```sh
make -C firmware/experiments/07_onboard_tension/host_test
firmware/experiments/07_onboard_tension/host_test/emg_host docs/data/06_forearm_emg/03_A_light_hard.log
.venv/bin/python analysis/validate_07_tension.py      # C vs float64 reference, levels, delay -> /tmp/tension07
```

## Validation on experiment 06 recordings (host, no board)

`analysis/validate_07_tension.py` compares the float32 C code with a float64 Python reference hop by hop: levels, saturation and calibration flags match exactly; RMS differs by at most 3.4e-4 mV.

Calibration CV limit: in experiment 06, the coefficient of variation of 50 ms RMS values was 0.24-0.44 in relax phases and 0.26-0.51 during efforts (0.98 in the saturated chord), so it does not separate relax from effort. With a limit of 0.3, segment A never calibrated in 75 s (10 attempts rejected); 0.5 accepts relax at the first attempt in A and B. The limit is overridable (`-DEMG_CAL_MAX_CV=...`) for host experiments. Effort periods are mainly kept out of the baseline by the 15 mV limit.

Correct level share in the phases' analysis windows (first 1.5 s after each cue skipped), calibrating 0.5-5.5 s after boot:

| | Level changes | Relax | Medium | Hard |
|---|---|---|---|---|
| A, no hysteresis | 66 | 93.0 % | 77.3 % | 100 % |
| A, hysteresis | 54 | 91.2 % | 78.0 % | 100 % |
| B, no hysteresis | 140 | 74.5 % | 38.3 % | - |
| B, hysteresis | 110 | 67.2 % | 30.2 % | - |

The baseline from before each recording (A 4.49 mV, B 5.82 mV) is lower than the relax level during it (experiment 06: 5.44 and 7.36 mV), which inflates the normalized values; B's relax after the first chord sits at 1.32-1.43x, close to the medium thresholds.
